# 最终仓库集成与服务器验证（2026-10-30）

## 原则与版本

- 运行时只读取题面和接口；开发用官方 judge 独立运行，参考实现和测试台不进入模型上下文。
- 最终仓库为 `40070_rtlagent`，此前 `rtl_api_agent` 的结果只能作为设计依据，不能代替最终包实测。
- 修改按逻辑分组提交；服务器使用新建的隔离目录，不修改对照项目 `/workspace/rtlagent2026`。
- 不因一个失败反复补丁：先覆盖不同题型，区分 RTL 错误、checker 错误和环境问题。

## 本轮共性修正

1. **反馈拓扑的检查器误判**：明确右移、XOR、Galois、抽头、种子、采样边沿及复位的规格，才使用程序化 recurrence。位宽和抽头由题面提取，不匹配任务 ID，不读取候选实现。缺失、冲突或超出支持范围时退回通用 checker 流程。
2. **数据值与协议进度混淆**：串行技能和 checker 提示明确每个数据采样边沿都推进计数，包括值为零的位；覆盖全零、混合数据与错误 stop，不额外假定题面未明确的输出周期。
3. **验证边界**：Galois oracle 包含同步复位的 off-edge 保持、on-edge 种子恢复及重启序列；测试应确认正确分布式反馈通过，Fibonacci 变异失败。

后续测试结果、源码标识与 agent/judge 独立耗时在验证完成后补充。未完成的测试不记为通过。
