# 单题时限与候选保留

接口依据为 [API_CONTRACT.md](API_CONTRACT.md)。正式单题总墙钟为 900 秒，
包含排队、生成、工具检查、修复、回收及结果取回。

## 工作预算

| 阶段 | 默认上限或动作 |
| --- | --- |
| RTL 生成/修复请求 | 240 秒；从剩余预算预留最多 180 秒用于检查，预留量不超过剩余预算的 35% |
| 编译 / 综合 / 仿真 | 120 / 180 / 120 秒，并受剩余工作预算限制 |
| 模型 checker 生成 / 复核 | 单次 150 / 45 秒，生成、复核、重建和仿真共享每轮最多 240 秒 |
| 已有候选且不足 60 秒 | 不开启新一轮 RTL 修复 |
| 第 870 秒 | agent 闹钟中断工作并保留结果 |
| 第 880 秒 | 服务向仍在运行的单题进程组发 SIGTERM |
| 最多再等待 5 秒 | 必要时发 SIGKILL |
| 随后最多 3 秒 | 回收该题子进程，再发布已有结果 |

各时点以请求抵达服务端为起点。排队与输入准备时间从预算扣除；剩余不足 20 秒
的排队任务发布空结果。预算使用 `time.monotonic()`，trace 时间戳使用 Unix 时间。
网络传输及外部查询需占用余量，900 秒不是可全部用于模型生成的预算。

checker 预算分别由 `AGENT_CHECKER_GENERATION_S`、`AGENT_CHECKER_REVIEW_S`、
`AGENT_CHECKER_TOTAL_S` 设置；旧的 `AGENT_CHECKER_S` 仅作为生成上限的兼容入口。
进入 checker 阶段时，为后续 RTL 修复预留最多 180 秒，且不超过剩余时间的 35%。
生成前保留 45 秒复核及 30 秒仿真余量，不启动不足 30 秒的生成请求。
复核传输或 JSON 协议失败最多重试一次同一份 checker；明确拒绝才独立重建。
生成或重建最多三次，已判无效的相同回复不会重复送审。任何未批准的模型 checker
均不执行，生成器和复核器均不读取候选 RTL 或独立判题夹具。

## 候选与超时处理

候选按接口、明确语义、编译、综合、自检证据逐级排序，更优候选立即原子写入
`solution.v`。错误接口或不完整模块不进入候选池；较差的新候选不覆盖已有结果。
生成错误、信号中断或工具超时后返回已保存候选；无候选时返回空结果。

自检须完成非零比较、无失配、无 unknown expected/mask，并打印完整通过标志。
编译或综合通过不能单独标记功能接受。自检接受也不保证通过独立 judge。

Vivado 继承单题进程组；单工具超时清理其后代，服务结束本题时清理并回收整组。
常驻模型由 `start.sh` 使用独立会话启动。任务 trace 只保留完整 JSONL 行。

## 模型与基线

原版 `baseline.py` 和 `run_baseline.sh` 不修改。模型、量化、上下文和 manifest
思考配置共用；基线温度、单次请求、840 秒请求上限等保持赛事方原口径。
对外服务为 agent 和 baseline 使用相同的排队与进程监督。

模型服务不启用 `MODEL_API_KEY`，因为原版基线不发送该鉴权头；外部投题接口仍鉴权。
直接调用 `run.sh` 时也有 agent 总预算闹钟，但不经过 HTTP 排队和结果查询链路。

## 时间统计

`agent.wall_s` 包含模型与工具，独立 `judge_process.wall_s` 另列。
`llm_wall_s` 统计成功返回请求；失败等待单列，已记录的成功与失败合计为
`llm_recorded_wall_s`。进程硬中止前未记录的调用终点不能追溯估算。
完整 HTTP 900 秒边界、干净镜像重建和长期连续投题仍需单独验证。
