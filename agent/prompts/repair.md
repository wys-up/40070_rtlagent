## 本轮要做的事

1. 先定位第一条 `ERROR:`，后面的错误往往是它的连带结果。
2. 判断这是哪一类失败：
   - **接口不符** —— `interface mismatch`、`cannot find port`、`Module <X> not found`。
     照接口重写模块头，端口名一个字都不要改。这类失败得分为 0，优先处理。
   - **语法错误** —— `VRFC 10-4982 syntax error`，多半是模块头缺分号、
     `begin`/`end` 不配对、位宽写法有误。
     过程赋值的 output 应直接在 ANSI 模块头改成 `output reg` 或 `output logic`。
     不要保留头部 `output out` 又在模块体加 `reg out;`，这会触发 ANSI 重复声明。
   - **不可综合的构造** —— `Synth 8-280`、`Synth 8-6156`。把 `real`、延时、
     文件 IO 之类去掉。
   - **意外的锁存器或多驱动** —— 组合逻辑分支没写全，或同一信号在两个 always
     块里被赋值。
   - **危险警告** —— 越界、`VRFC 10-3705`、`Synth 8-6858/6859` 即使工具退出码为 0
     也必须修复。检查非二次幂末端补零、同一变量的所有写者。明确要求的锁存器除外。
   - **功能失配** —— `AGENT_MISMATCH` 给出时间、输入/周期标签、实际和期望值。
     从原规格独立推导这一拍的状态与输出，检查多一拍、复位范围、位序和边界。
     只修 RTL，不能删除检查或改变接口。若反馈与题面有歧义，遵循题面明确陈述。
3. **只改必要的部分。** 上一轮已经正确的地方不要重写，重写会引入新的错误。
4. 若同一个错误连续两轮未解决，换一条思路，不要在同一处继续微调。

如果诊断属于语法、接口、声明或过程归属问题，修复时保持原有状态转移条件、计数终值、
位序、复位优先级、反馈/算术表达式和输出周期。多驱动修复只移动冲突寄存器的赋值，
不要借编译修复重写 FSM、替换 next-state 方程或改变串行/LFSR 行为。除非工具证据明确
指出功能错误，否则修复前后应对所有规格输入序列行为等价。

输出完整的修正后文件，仍然只输出一个 ```verilog 代码块，块外不要有任何文字。
